# Internationalization

Tidewater uses one small, dependency-free i18n interface for its browser UI and game copy. The active locale is chosen once at startup from `navigator.languages` (then `navigator.language`). The first supported match wins; Chinese script/region tags resolve to Simplified or Traditional Chinese. Unsupported preferences fall back to English. Add `?lang=ja` (or another supported code) to the URL to preview a locale.

Supported locales are English (`en`), Simplified Chinese (`zh-CN`), Traditional Chinese (`zh-TW`), Japanese (`ja`), Spanish (`es`), Russian (`ru`), German (`de`) and French (`fr`).

## Catalog layout

Each locale has its own file under `src/i18n/locales/`. A file exports one resource bundle with `messages` and `plurals`; translators can edit one language without navigating a combined table. `locales/index.js` is only the registry and uses dynamic imports, so startup loads the selected locale and the English plural fallback instead of bundling every translation into the initial download. English copy is the source text passed to `t`; the English catalog contains its plural forms.

## Message API

Import the shared API from `src/i18n/index.js`:

```js
import { t, tn, formatNumber, formatCurrency, formatDate } from '../i18n/index.js';

toast( t( 'Filled up · {litres} L', { litres: formatNumber( litres ) } ) );
toast( tn( 'fish.sold', count, { amount: formatCurrency( total ) } ) );
```

- `t(source, values)` translates an English source message and substitutes named `{placeholders}`. Missing translations use the English source.
- `tn(key, count, values)` selects the active locale's `Intl.PluralRules` category. Add the English form under `plurals` in `en.js` and localized forms under `plurals` in that locale's file.
- `formatNumber`, `formatCurrency` and `formatDate` use the active locale's `Intl` formatters.
- `translateHTML` and `localizeDOM` localize existing DOM copy and supported text attributes. For new dynamic copy, prefer `t`/`tn` at the point the text is created so values and grammar remain explicit.

## Adding copy

Use an English source phrase with `t(source, values)` for singular copy and add its translation under `messages` in each locale file. Keep named placeholders identical across translations. For count-dependent copy, use a stable key with `tn(key, count, values)` and add each language's plural forms under `plurals`. Missing translations fall back to the English source. User-visible copy should go through the shared interface rather than a module-local dictionary or direct, untranslated DOM assignment.

To add a locale, add its resource bundle in `src/i18n/locales/` and register a dynamic loader in `src/i18n/locales/index.js`. The shared interface, formatting helpers and callers do not need locale-specific branches.
